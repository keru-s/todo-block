# 全量备份采用版本化 JSON、保守合并与独立导入恢复点

Todo Block 的全量导入导出用于备份和跨设备迁移，不定义为离线双向同步。规范备份格式使用带版本号的 JSON，完整保存 Todo 与日期分组的可持久化数据，但不保存选择、焦点、当前页面、偏好或操作历史；所属日期按日历日期保存，不做跨时区换日，创建与更新时间保存为绝对时间。旧版本应用遇到不认识的备份版本或任何非法记录时拒绝整个导入，不做部分恢复。

导入采用保守的备份合并：Todo 只以稳定身份判断是否为同一项，不根据标题或内容猜测去重；本地仅有的 Todo 始终保留，备份中缺失不表示删除，因此 V1 不传播删除也不维护 tombstone。相同身份的 Todo 以整项 `updatedAt` 做 Last Write Wins，导入版本较新时更新，本地较新或时间相同时保留本地；不做字段级合并。日期分组按规范化日期识别同一分组，而不是照搬 Todo 的身份规则。结构并发修改造成的极端父子层级冲突在 V1 中接受为备份迁移的限制，不升级为同步协议。

真正修改数据前必须先生成并展示导入预览，给出新增、更新、保留本地与无变化的统计，并允许展开查看更新和冲突的具体差异与原因；预览不提供逐条人工改写自动合并结论。导入文件必须先完整解析和校验，整个合并计划要么完整应用，要么不改变任何数据。处于本地持久化失败的待保存状态时禁止导入；导出则允许从当前内存中的最新用户数据生成备份。

全量导入不进入应用的 Undo/Redo 操作历史，导入成功后清空既有操作历史。为防止实现错误或导入结果不符合预期，每次导入前必须先持久化一份“导入恢复点”；恢复点创建失败则禁止导入。应用只保留最近一次导入前的恢复点，下一次成功导入覆盖旧恢复点，普通编辑和应用重启不会删除它。用户可通过文件菜单执行“恢复到最近一次导入前”，该操作以精确恢复替换当前 Todo 与日期分组，而不是再次执行备份合并，因此会同时移除导入后新增的数据和导入后的其他修改；执行前必须明确确认风险，恢复成功后消费该恢复点并清空操作历史。

## Consequences

- 备份文件是可演进的数据契约，schema 变更必须通过版本号显式管理，不能让旧版本静默忽略未知语义。
- 备份导入只解决迁移与安全合并，不承担多端删除传播、字段级并发合并、时钟纠偏或真正的双向同步。
- 相同内容但身份不同的 Todo 永远视为不同待办；相同身份冲突时接受系统时钟作为 V1 的版本先后依据。
- 导入实现必须保留备份中的原始创建与更新时间，不能复用会把 `updatedAt` 改成当前时间的普通编辑恢复路径。
- 导入恢复点与操作历史是两套不同语义：前者是高风险数据操作的单一持久化安全点，后者只服务当前运行期的普通用户操作。
- 文件菜单提供“导入备份… / 导出备份… / 恢复到最近一次导入前…”，没有可用恢复点时恢复入口不可用。
